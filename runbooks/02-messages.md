# 02. Повідомлення

[Усі теми](README.md) · [Попередня](01-model.md) · [Наступна](03-function.md)

**Перед початком:** код із гілки `step-01-model`. **Результат теми:** `step-02-messages`. Змінюємо лише `src/`.

## Що робимо й навіщо

Відокремлюємо правила system від завдання user. Масив messages стане історією: згодом ми додамо сюди запити моделі на інструменти й результати.

### Що означає type ModelMessage

`ModelMessage` із пакета `ai` описує повідомлення: роль system, user, assistant або tool і допустимий вміст. `import type` потрібен TypeScript для перевірки коду; під час виконання це не окремий обʼєкт і не запит до моделі.

### Що таке системний промпт

Поле system задає правила поведінки моделі на час запиту. Повідомлення з роллю `user` містить конкретне завдання людини. На цьому етапі правило лише одне: відповідати українською. Коли введемо агента news у темі 04, розкладемо його правила за роллю, метою, діями та обмеженнями. Текст промпту не виконує функції й не перевіряє дозволи: для цього потрібен код.

### System і user під капотом

- `system` задає загальні правила й роль. `user` містить поточне завдання. Це один виклик моделі, а не два окремі запити.
- У `generateText` system є окремим полем. Адаптер Groq перетворює його на повідомлення `{ role: 'system', content: ... }`, а завдання надсилає з `role: 'user'` у тому самому HTTP-запиті.
- System має вищий пріоритет інструкцій. Це не програмна гарантія: дозвіл на запис перевіримо кодом у темі 12.
- Обидва тексти займають контекст і враховуються як вхідні токени. У темі 03 побачимо фактичне тіло запиту через `TRACE=1`.

### Які ролі побачимо далі

| Роль | Що передаємо в нашому агенті | Коли додаємо |
|---|---|---|
| `system` | Загальні інструкції агента | У цій темі, окремим полем `generateText` |
| `user` | Завдання людини | У цій темі, у `messages` |
| `assistant` | Відповідь моделі або її запит на тул | У темі 07, коли збираємо історію |
| `tool` | Результат виконаної функції | У темі 07, після виконання тула |

Назва ролі показує джерело повідомлення. Коментар із HN повернемо як дані тула; він не має ставати новою системною інструкцією.

### Чому інструкція англійською

`Reply in Ukrainian.` означає «Відповідай українською». Інструкції й описи тулів пишемо стислою англійською, а пояснення для тебе — українською. Так часто потрібно менше токенів, але конкретна економія залежить від тексту й токенізатора моделі. Відсоток без виміру не обіцяємо. Мова інструкції не змінює бажану мову відповіді.

## Чого бракує зараз і що зміниться

Поле `prompt` містить один текст. Нам треба окремо передавати завдання людини й правила, а пізніше зберігати відповіді та результати дій. Для цього вводимо messages.

- process.argv[2] читає завдання з командного рядка; trim прибирає зайві пробіли.
- Перевірка !task не дає запустити запит без завдання. Тему й бажаний результат задає людина у команді.
- role: user позначає завдання користувача. system задає правила поведінки на час запиту.
- Після зміни завдання можна змінити командою запуску, не редагуючи код.

## Маленькі зміни

У `src/main.ts` додай ModelMessage до імпорту з ai:

```ts
import { generateText, type ModelMessage } from 'ai';
```

`process.argv` — аргументи запуску: елемент `[0]` містить шлях до Node, `[1]` — до програми, `[2]` — наше завдання. `?.trim()` прибирає пробіли, лише якщо аргумент існує. Без аргументу отримаємо `undefined`, із самими пробілами — порожній рядок; `!task` виявляє обидва випадки. `process.exit(1)` завершує програму з кодом помилки до звернення до моделі.

Після оголошення `model` прочитай і перевір завдання:

```ts
const task = process.argv[2]?.trim();
if (!task) {
  console.error('Помилка: передай задачу. Наприклад: npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."');
  process.exit(1);
}
```

Порожнє введення має завершити програму до HTTP-запиту. `ModelMessage[]` означає масив повідомлень. У першому обʼєкті `role` вказує автора, `content` містить текст завдання. Після перевірки створюємо повідомлення:

```ts
const messages: ModelMessage[] = [{ role: 'user', content: task }];
```

У generateText прибери поле prompt. На його місце встав:

```ts
system: 'Reply in Ukrainian.',
messages,
```

Перед викликом моделі можеш подивитися, що передаєш:

```ts
console.log('Повідомлення:', messages);
```

У команді `npm start -- "Твоя задача"` подвійний дефіс передає решту аргументів нашій програмі. Лапки тримають все завдання одним аргументом, навіть якщо в ньому є пробіли.

Окремо перевір відсутнє завдання та пробіли:

```bash
npm start
npm start -- "   "
```

В обох випадках очікуємо «Помилка: передай задачу» й код завершення 1. Тема не підставляється автоматично: її треба явно назвати у завданні.

## Перевірка

```bash
npm run check
npm test -- --test-name-pattern "^0[0-2] "
npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
```

**Автоматична перевірка:** 8 тестів без мережі. Усі тести вже є в [test/harness.test.mjs](../test/harness.test.mjs) та [test/runbooks.test.mjs](../test/runbooks.test.mjs). Число на початку назви тесту відповідає етапу; команда запускає цей і попередні етапи.

**Очікуємо:** одне завдання user і відповідь моделі. Інструментів ще немає; текст про дискусії не означає, що дані перевірені.

**Якщо не так:** якщо тип role не підходить, звір ModelMessage[]. Власне завдання передай через npm start -- "Твоє завдання".

## Якщо не встиг: готова гілка й наступна тема

Ця гілка містить **результат теми 02**. Збережи свою спробу й створи робочу гілку від готового коду:

```bash
git add src
git diff --cached
git diff --cached --quiet || git commit -m "Моя спроба етапу 02"
git fetch origin
git switch -c work-03 origin/step-02-messages
npm run check
npm test -- --test-name-pattern "^0[0-2] "
```

Власний коміт залишився у попередній гілці. Якщо work-03 вже існує, обери нове імʼя, наприклад work-03-retry. .env і node_modules залишаються на місці. Відкрий [ранбук 03](03-function.md) в тому самому редакторі: усі ранбуки й тести доступні в кожній гілці.

Якщо завершив самостійно, продовжуй у своїй гілці за наступним ранбуком; брати готовий код необовʼязково.

## Готовий код

Очікуваний вміст змінених файлів після теми. Інші файли залишаються без змін.

<details>
<summary>src/main.ts</summary>

```ts
import { generateText, type ModelMessage } from 'ai';
import { groq } from '@ai-sdk/groq';

const maxOutputTokens = 512;
const modelTimeoutMs = 60_000;

const model = groq(process.env.GROQ_MODEL || 'qwen/qwen3.8-27b');

const task = process.argv[2]?.trim();
if (!task) {
  console.error('Помилка: передай задачу. Наприклад: npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."');
  process.exit(1);
}
const messages: ModelMessage[] = [{ role: 'user', content: task }];

const reply = await generateText({
  model,
  system: 'Reply in Ukrainian.',
  messages,
  maxRetries: 0,
  maxOutputTokens,
  abortSignal: AbortSignal.timeout(modelTimeoutMs),
});

console.log('Причина завершення:', reply.finishReason);
console.log('Відповідь:', reply.text);
```

</details>
