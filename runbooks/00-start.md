# 00. Підготовка до воркшопу

[Усі теми](README.md) · [Далі: перший запит](01-model.md)

## Що робимо й навіщо

**До заняття встанови Node.js, Git і редактор та підготуй API-ключ одного провайдера: Groq, OpenAI, Anthropic, Grok або OpenRouter. Репозиторій клонуватимемо разом на початку воркшопу — заздалегідь цього робити не потрібно.** На воркшопі збиратимемо агента, який шукає обговорення на Hacker News і зберігає дайджест. Для основного прикладу залежності й налаштування вже готові; під час практики змінюватимемо `src/`. Якщо обереш іншого провайдера, на занятті додамо його пакет і налаштування.

Виділи приблизно 30 хвилин на підготовку. Достатньо одного облікового запису з доступом до API. Якщо вже маєш такий доступ, можеш використати його. Репозиторій публічний: для читання ранбуків і клонування обліковий запис GitHub не потрібен.

## 1. Встанови Node.js і Git

Використовуємо **Node.js 26.9.0 Current**. npm встановлюється разом із Node. Для коду підійде твій редактор або [VS Code](https://code.visualstudio.com/download).

| ОС | Що встановити | Де виконувати команди |
|---|---|---|
| Windows | [Node.js](https://nodejs.org/en/download) — Windows Installer `.msi`; [Git for Windows](https://git-scm.com/install/windows) з Git Bash. Залиш типові налаштування й додавання до PATH. | **Git Bash** із меню Start. У VS Code: Terminal → Select Default Profile → Git Bash. |
| macOS | [Node.js](https://nodejs.org/en/download) — macOS Installer `.pkg`. Виконай `git --version` і погодься встановити Command Line Tools, якщо система запропонує. | Terminal |
| Linux | Git — через пакетний менеджер; Node — через [nvm](https://github.com/nvm-sh/nvm#install--update-script), потім `nvm install 26.9.0` і `nvm use 26.9.0`. | Terminal |

На Ubuntu/Debian Git встановлюється командою `sudo apt install git` після `sudo apt update`. На macOS, якщо Git відсутній і запрошення не зʼявилось, виконай `xcode-select --install`.

Відкрий новий термінал і перевір:

```bash
node --version
npm --version
git --version
```

Очікуємо Node `v26.9.0`, а також версії npm та Git. Якщо команда не знайдена — перезапусти термінал після встановлення.

## 2. Обери провайдера й підготуй API-ключ

Провайдер — сервіс, через який наша програма звертатиметься до моделі. API-ключ дає програмі доступ до цього сервісу. Модель працюватиме на його серверах: завантажувати її на ноутбук не потрібно.

**Обери один варіант.** Якщо хочеш іти точно за готовим кодом і тестами, обери Groq. Якщо вже користуєшся іншим API, у першій темі є [приклади його підключення](01-model.md#обери-провайдера).

| Провайдер | Де зареєструватися й створити ключ | Модель для першого запиту | Що перевірити до заняття |
|---|---|---|---|
| **Groq** | [Groq Console](https://console.groq.com/) → [API Keys](https://console.groq.com/keys) → Create API Key | `qwen/qwen3.8-27b` | Для Free plan картка й поповнення не потрібні. Перевір [ліміти акаунта](https://console.groq.com/settings/limits): безкоштовний доступ може вимагати пауз між запитами. |
| **OpenAI** | [OpenAI Platform](https://platform.openai.com/) → [API keys](https://platform.openai.com/api-keys) | `gpt-4.1-mini` | Доступ до моделі, білінг API та ліміти. |
| **Anthropic / Claude** | [Claude Console](https://platform.claude.com/) → API keys | `claude-haiku-4-5` | Доступ до моделі, баланс для API та ліміти. |
| **Grok / xAI** | [xAI Console](https://console.x.ai/) → API Keys | `grok-4.7` | Доступ до моделі, білінг API та ліміти. |
| **OpenRouter** | [OpenRouter](https://openrouter.ai/) → [Keys](https://openrouter.ai/settings/keys) → Create Key | `openai/gpt-4.1-mini` | Для цієї моделі потрібен баланс. Безкоштовні моделі мають окремі квоти; вони не гарантують роботу без `429`. |

**Grok і Groq — різні сервіси.** Grok — моделі від xAI. Через Groq у нашому прикладі запускаємо Qwen. OpenRouter надає доступ до моделей різних виробників через один API.

У кабінеті вибраного сервісу:

1. Увійди або створи обліковий запис.
2. Перевір, чи доступна модель із таблиці та чи готовий акаунт до запитів: тариф, баланс, квоти. Приклади моделей не означають, що доступ до них безкоштовний.
3. Створи API-ключ із назвою `harness-workshop` і збережи його в менеджері паролів або іншому приватному сховищі. Ключ знадобиться на занятті; у чат його не надсилай.

Наявність доступу до чату ще не підтверджує доступ до API. Для воркшопу потрібен саме API-ключ вибраного сервісу. Ключі різних провайдерів не взаємозамінні.

**До заняття все готово, якщо:** термінал показує версії Node.js, npm і Git, редактор відкривається, а ти зберіг API-ключ і знаєш, яку модель використовуватимеш. На цьому зупинися. Клонування, встановлення пакетів, створення `.env` і перший запит зробимо разом на воркшопі.

## На воркшопі: клонуємо проєкт

Цей розділ виконаємо разом на початку заняття. [Репозиторій](https://github.com/genkovich/harness-workshop) публічний, запрошення не потрібне.

У терміналі перейди в папку, де зберігаєш проєкти, і виконай:

```bash
git clone --branch start https://github.com/genkovich/harness-workshop.git
cd harness-workshop
npm ci
git switch -c work-01
```

Відкрий папку `harness-workshop` у редакторі. `npm ci` встановлює пакети й створює `.env`. Наявний `.env` не перезаписується.

Для локальних комітів задай своє імʼя й email:

```bash
git config user.name "Твоє імʼя"
git config user.email "твій-email@example.com"
```

Під час практики працюємо у власній локальній гілці. Відправляти коміти в репозиторій організатора не потрібно.

## На воркшопі: додаємо ключ

Відкрий `.env` у корені проєкту. Якщо обрав **Groq**, встав збережений ключ:

```dotenv
GROQ_API_KEY=твій_ключ_із_Groq
GROQ_MODEL=qwen/qwen3.8-27b
APPROVED=0
```

`.env` уже виключений із Git. `GROQ_API_KEY` дає програмі доступ до Groq, `GROQ_MODEL` вибирає модель, а `APPROVED=0` залишає запис дайджесту без дозволу на фінальному етапі практики. Суфікс `:free` до назви моделі додавати не потрібно.

Якщо обрав **OpenAI, Anthropic, Grok або OpenRouter**, додай змінні `.env` зі [свого прикладу в темі 01](01-model.md#обери-провайдера). Там само є команда встановлення адаптера й код підключення. `APPROVED=0` залиш. Заповнювати `GROQ_API_KEY` для іншого провайдера не потрібно.

## Перевірка проєкту на воркшопі

З папки проєкту виконай:

```bash
npm run check
npm test -- --test-name-pattern "^00 "
npm start
```

`npm run check` перевіряє типи без запуску агента. `npm test` запускає готові тести; `--test-name-pattern "^00 "` вибирає лише підготовку за номером у назві. `npm start` запускає `src/main.ts`.

Має вийти:

- перевірка типів без помилок і **4 успішні тести**;
- у гілці `start` команда `npm start` друкує «TypeScript працює».

Ці перевірки не використовують твій API-ключ. Для **Groq** додатково виконай:

```bash
npm run setup:check
```

Очікуємо **«ключ працює; tool call отримано»**. Якщо обрав інший провайдер, пропусти цю команду: вона звертається лише до Groq. Доступ до обраного API перевіримо першим запитом у [темі 01](01-model.md#обери-провайдера). Готові тести наступних тем також привʼязані до формату Groq; вони не перевіряють альтернативні підключення.

Лише остання команда робить один запит до моделі з бюджетом виходу 128 токенів; у навчальному коді починаємо з 512. Це бюджет одного запиту, а хвилинна квота спільна для всіх запусків: кілька запитів поспіль усе одно можуть потребувати паузи. Тести працюють без мережі. Перевірка API не змінює твій тариф Groq і не визначає, чи акаунт уже платний.

## Якщо щось не працює

| Помилка | Що зробити |
|---|---|
| GitHub показує 404 | Звір адресу з командою клонування вище. |
| Немає `.env` | Виконай `npm run prepare`. На Windows перевір, що файл не названо `.env.txt`. |
| `401` | Звір ключ у `.env`: він має належати вибраному провайдеру. Для Groq це `GROQ_API_KEY`. |
| `403` або `404` від API | Звір назву моделі й доступ до неї в кабінеті провайдера. Для Groq назву задає `GROQ_MODEL`. |
| `429: Request too large / OTPM` | Один запит перевищує ліміт виходу. Зменш `maxOutputTokens`; сама пауза не виправить завеликий запит. |
| `429: Rate limit reached` | Перевір квоти провайдера; для Groq це сторінка [Limits](https://console.groq.com/settings/limits). Якщо є `Retry-After`, зачекай зазначений час. Не запускай перевірку багато разів поспіль. |
| Немає виклику інструмента або відповідь обрізана | Передай організатору текст помилки без ключа. |

На 21.09.2026 для цієї моделі Groq Free зазначає **30 запитів/хв, 1 000/добу, 8 000 токенів/хв і 200 000/добу**. У частини акаунтів окремо діють **ITPM** (вхід) та **OTPM** (вихід). Наприклад, за OTPM 1000 запит із бюджетом виходу понад 1000 буде відхилений навіть після паузи. Особисті ліміти дивись у кабінеті. Після першого циклу окремо пройдемо [крок 08б](08b-limits.md): обмежений повтор тимчасово невдалого запиту. Один запуск агента може містити кілька запитів; коментарі та історія теж займають токени. [Документація лімітів](https://console.groq.com/docs/rate-limits).

Після успішної перевірки відкрий [етап 01](01-model.md). Якщо відставатимеш на занятті, у кінці кожної теми є команди переходу на готову контрольну гілку. Ранбуки й тести доступні в кожній гілці.
