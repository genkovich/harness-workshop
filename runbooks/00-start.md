# 00. Підготовлена основа

[Усі теми](README.md) · [Наступна: перший запит](01-model.md)

## Що робимо й навіщо

Перевіряємо встановлення й перший локальний запуск. Конфігурація та дані вже готові, тому на занятті можна зосередитися на src/.

Потрібні Node.js **22.19 або новіший**, Git, доступ до приватного репозиторію та ключ OpenRouter із балансом для живих запитів. Перевір версію командою `node --version`.

## Перед заняттям

```bash
git clone --branch start https://github.com/genkovich/harness-workshop.git
cd harness-workshop
npm ci
git switch -c work-01
```

npm ci встановлює версії з package-lock.json та створює .env із .env.example, якщо його немає. Наявний .env не перезаписується. Один раз встав OPENROUTER_API_KEY у .env. Ключ не комітиться. Далі на практиці змінюємо лише src/.

## Які пакети вже встановлені

| Пакет | Для чого він у нашому коді | Де розбираємо |
|---|---|---|
| `@openrouter/ai-sdk-provider` | Адаптер: підключає API OpenRouter до AI SDK; openrouter(...) вибирає модель. | [Етап 01](01-model.md) |
| `ai` | AI SDK від Vercel: generateText робить виклик, tool описує тул, типи задають форму історії. | [Етап 01](01-model.md), [етап 04](04-tools.md) |
| `zod` | Схеми аргументів і перевірка фактичних даних: customerId має бути додатним цілим числом. | [Етап 04](04-tools.md), [етап 06](06-execute.md) |
| `typescript` | Перевірка типів командою npm run check. | На кожному етапі |
| `tsx` | Запуск файлів TypeScript у Node.js без окремого ручного збирання. | npm start і тести |
| `@types/node` | Описи типів Node.js: process, файли та інші вбудовані API. | Перевірка типів |

node:fs, node:test і node:assert — вбудовані модулі Node.js. Їх не встановлюємо через npm. Деталі основних пакетів та посилання на офіційні документи є біля першого імпорту в темах 01 і 04.

## Перевірка

```bash
npm run check
npm test -- --test-name-pattern "^00 "
npm start
```

Очікуємо 2 тести підготовки та «TypeScript працює». Тести без мережі: [сценарії агента](../test/harness.test.mjs), [середовище та ранбуки](../test/runbooks.test.mjs). Файл [openrouter.mock.mjs](../test/openrouter.mock.mjs) підмінює HTTP тільки в тестах; src працює зі справжнім адаптером.

Повний npm test призначений для готового рішення. На ранніх етапах запускай команду з поточної теми: майбутні функції ще не написані. Всі тести можна читати відразу, вони однакові в кожній гілці.

Якщо Node старіший за 22.19, онови його перед npm ci. Якщо немає доступу до GitHub, потрібне запрошення власника. Якщо .env не зʼявився через вимкнені lifecycle scripts, виконай npm run prepare перед заняттям.

## Як переходити між гілками

Назва step-05-call означає **готовий результат етапу 05**. Щоб почати 06, бери цю точку й відкривай runbooks/06-execute.md. У кінці кожної теми є точні команди збереження своєї спроби й переходу. Власні коміти залишаються у твоїх робочих гілках; reset або restore не потрібні.

Ранбуки й тести однакові в усіх контрольних точках. Тримай їх відкритими в редакторі й змінюй лише src/. Почни [етап 01](01-model.md).
