# 00. Підготовка до воркшопу

[Усі теми](README.md) · [Наступна: перший запит](01-model.md) · [Перевірка залежностей через Context7](dependencies.md)

## Що робимо й навіщо

До заняття встановлюємо Node.js, Git і редактор, отримуємо код та підключаємо безкоштовну модель. Перевірка окремо покаже, що працює локальне середовище і що API приймає запити з тулами. На самому занятті змінюємо лише src/.

Підготуй приблизно 30–45 хв, інтернет, облікові записи GitHub і OpenRouter. Картка й поповнення OpenRouter для описаного маршруту не потрібні. Docker, Python, локальну LLM та окремий сервер встановлювати не потрібно.

## 1. Встанови Node.js, Git і редактор

Node.js виконує нашу програму, npm встановлює її пакети. Git дає код і контрольні гілки. Редактор потрібен для src/ і ранбуків; підійде вже знайомий редактор або [VS Code](https://code.visualstudio.com/download).

Використовуємо **Node.js 26 Current**; на 21.09.2026 перевірена версія **26.9.0**. npm входить до Node.js. Current — актуальний стабільний реліз, ще не LTS. Версії пакетів зафіксовані в package-lock.json: учасники виконують npm ci. [Офіційне завантаження Node.js](https://nodejs.org/en/download).

### Windows: Node.js і Git Bash

1. На сторінці Node.js вибери Windows, гілку 26 Current та Installer `.msi`. Для звичайного Intel/AMD-компʼютера обирай x64, для Windows on ARM — ARM64.
2. Запусти інсталятор із типовими налаштуваннями. Залиш npm і додавання до PATH; додаткові build tools для цього репозиторію не потрібні.
3. Встанови [Git for Windows](https://git-scm.com/install/windows). Залиш доступ Git із командного рядка та Git Bash.
4. Закрий старі термінали й відкрий **Git Bash** із меню Start. Саме в ньому виконуватимемо команди ранбуків. WSL для цього не потрібен.
5. У VS Code можна вибрати Terminal → Select Default Profile → Git Bash, потім відкрити новий термінал.

```bash
node --version
npm --version
git --version
```

Має бути Node `v26.9.0`, версія npm і версія Git. Якщо команда не знайдена, спочатку перезапусти термінал після встановлення. Не встановлюй іншу копію Node навмання.

### macOS: Node.js і Terminal

1. На сторінці Node.js вибери macOS, 26 Current та Installer `.pkg`.
2. Встанови пакет, відкрий новий Terminal. На Mac з Apple Silicon використовуй відповідний ARM64-дистрибутив, якщо сайт просить вибір архітектури.
3. Виконай git --version. Якщо macOS запропонує Command Line Tools, погодься й дочекайся встановлення. Якщо запрошення не зʼявилося, виконай xcode-select --install. Повний Xcode для практики не потрібен.

```bash
node --version
npm --version
git --version
```

Очікуємо Node `v26.9.0` і доступні npm та Git. [Варіанти встановлення Git](https://git-scm.com/book/en/v2/Getting-Started-Installing-Git).

### Linux: приклад для Ubuntu/Debian

Відкрий Terminal. Спочатку встанови Git і засоби завантаження:

```bash
sudo apt update
sudo apt install -y git curl ca-certificates
```

Для Node використаємо nvm, менеджер версій. Встанови його за [офіційною інструкцією nvm](https://github.com/nvm-sh/nvm#install--update-script); перевірена команда:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.8/install.sh | bash
```

Команда завантажує й запускає інсталятор із репозиторію nvm. Потім відкрий новий Terminal або підключи nvm у поточному:

```bash
. "$HOME/.nvm/nvm.sh"
nvm install 26.9.0
nvm use 26.9.0
nvm alias default 24
node --version
npm --version
git --version
```

Якщо nvm не знайдений, перевір повідомлення інсталятора про файл профілю shell. Для Fedora/Arch встанови Git і curl своїм пакетним менеджером, а Node — тим самим nvm. Не використовуй sudo для npm ci всередині проєкту.

### Однакова версія npm для всіх ОС

Після встановлення Node виконай у Git Bash (Windows) або Terminal (macOS/Linux):

```bash
npm install --global npm@12.0.2
npm --version
```

Очікуємо `12.0.2`. У PowerShell замість `npm` можна використовувати `npm.cmd`. Якщо Windows відмовляє в доступі до системної папки Node, виконай саме глобальне оновлення npm у терміналі адміністратора, потім повернись у звичайний термінал. На macOS після системного `.pkg` за помилки EACCES можна виконати `sudo npm install --global npm@12.0.2`; для nvm sudo не потрібен. Команди проєкту виконуй без адміністративних прав.

## 2. Отримай доступ до репозиторію

1. Створи обліковий запис на [GitHub](https://github.com/signup), якщо його немає.
2. Передай організатору свій GitHub username і прийми запрошення до приватного репозиторію.
3. Увійди в GitHub у браузері й відкрий [harness-workshop](https://github.com/genkovich/harness-workshop). Якщо бачиш 404, спочатку перевір доступ і правильний обліковий запис.

Вибери папку для навчальних проєктів. На Windows працюй у Git Bash, на macOS/Linux — у Terminal:

```bash
mkdir -p ~/workshops
cd ~/workshops
git clone --branch start https://github.com/genkovich/harness-workshop.git
cd harness-workshop
```

Якщо Git запропонує вхід через браузер, заверши його своїм GitHub-акаунтом. Якщо термінал просить пароль для HTTPS, пароль від GitHub не підходить: використай налаштований credential manager або [fine-grained personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) з доступом до цього репозиторію та Contents: Read-only. Токен вставляй у запит пароля, не в URL команди й не в чат. Доступ до приватного репозиторію все одно має бути наданий організатором.

Відкрий папку harness-workshop у редакторі через File → Open Folder. Команда code . теж працює, якщо редактор додав її до PATH.

## 3. Встанови готові залежності

```bash
npm ci
git switch -c work-01
```

npm ci встановлює точні версії з lockfile та створює .env із .env.example, якщо файла ще немає. Наявний .env не перезаписується. Якщо lifecycle scripts були вимкнені й .env немає:

```bash
npm run prepare
```

Для власних комітів налаштуй імʼя та email **в цьому репозиторії**, якщо Git ще їх не знає:

```bash
git config user.name "Твоє імʼя"
git config user.email "твій-email@example.com"
```

Email можна взяти з GitHub Settings → Emails, зокрема GitHub noreply. У командах заміни приклади своїми значеннями. Завантажувати власні коміти на GitHub під час практики не потрібно.

## 4. Зареєструйся в OpenRouter і створи ключ

1. Відкрий [OpenRouter](https://openrouter.ai/) і натисни Sign up. Обери доступний спосіб входу, заверши підтвердження email, якщо його просить сайт.
2. Після входу відкрий [API Keys](https://openrouter.ai/settings/keys).
3. Створи новий ключ із назвою, наприклад harness-workshop. Якщо є поле терміну дії, він має покривати день заняття.
4. Скопіюй секретний ключ у локальний .env. Не надсилай його організатору й не показуй на спільному екрані.
5. Не потрібно переходити в Add credits або додавати картку: нижче вибираємо саме безкоштовний endpoint.

Відкрий .env у редакторі та заповни:

```dotenv
OPENROUTER_API_KEY=твій_ключ_із_OpenRouter
OPENROUTER_MODEL=qwen/qwen3.8-27b:free
APPROVED=0
```

Заміни лише значення ключа; без кутових дужок і зайвих пробілів. На Windows переконайся, що файл називається .env, а не .env.txt. Файл уже в .gitignore. Підписка ChatGPT або Claude не замінює цей API-ключ.

## 5. Обери безкоштовну модель із тулами

Початковий вибір на 21.09.2026: **[Qwen3.8 27B (free)](https://openrouter.ai/qwen/qwen3.8-27b:free)**, ID `qwen/qwen3.8-27b:free`. У поточному каталозі input/output коштують $0, модель підтримує tools. Це перевірка каталогу, доступність саме твого ключа перевіримо наступною командою.

Щоб обрати іншу:

1. Відкрий [каталог моделей](https://openrouter.ai/models?max_price=0).
2. Знайди безкоштовний варіант із підтримкою **Tools / Tool calling**.
3. На його сторінці звір ціну input і output: обидві $0.
4. Скопіюй **точний API ID**, який закінчується на `:free`, у OPENROUTER_MODEL у .env. Назва моделі для показу й API ID — різні речі.
5. Повтори npm run setup:check. Налаштування підхоплюється під час наступного запуску.

Не прибирай суфікс :free: це інший endpoint, який може бути платним. Для відтворюваності група починає з одного погодженого ID. Безкоштовні моделі та їхня доступність можуть змінюватися; команда перевірки звертається до поточного каталогу. [Документація безкоштовних варіантів](https://openrouter.ai/docs/guides/routing/model-variants/free).

## 6. Перевірка перед заняттям

Спочатку без мережі:

```bash
npm run check
npm test -- --test-name-pattern "^00 "
npm start
```

У гілці start остання команда друкує «TypeScript працює». Тести перевіряють підготовку, ранбуки та діагностику; їм не потрібні гроші чи справжній ключ.

Тепер **один живий запит** до обраної безкоштовної моделі:

```bash
npm run setup:check
```

Очікуємо:

```text
Готово: qwen/qwen3.8-27b:free; ключ працює; tool call отримано.
Зроблено один запит до безкоштовної моделі. Можна починати етап 01.
```

Перевірка читає каталог, відхиляє платний ID або відсутність tools і робить один запит ready через той самий SDK. Нічого не бронює, не надсилає й не змінює у навчальних даних. Повний навчальний агент у start ще не написаний.

## 7. Як працюємо на трьох ОС

Усі команди bash у ранбуках підходять для **Git Bash на Windows, Terminal на macOS і bash/zsh на Linux**. Виконуй їх із папки harness-workshop. На наступних етапах задача передається явно:

```bash
npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
```

Починаючи з етапу 02, без задачі або з самими пробілами програма завершиться з помилкою до HTTP-запиту.

Для дебагу, починаючи з етапу 03:

```bash
TRACE=1 npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
```

Для етапу 12 порівняємо запуск із дозволом і без нього:

```bash
APPROVED=0 npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
APPROVED=1 npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
```

### Якщо користуєшся PowerShell

Git Bash залишається найпростішим способом копіювати команди уроків. У PowerShell npm.ps1 інколи блокується execution policy: використовуй npm.cmd, не змінюючи політику системи.

```powershell
npm.cmd ci
npm.cmd run setup:check
npm.cmd start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
```

Змінна задається окремою командою й діє до її видалення:

```powershell
$env:TRACE = "1"
npm.cmd start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
Remove-Item Env:TRACE
```

```powershell
$env:APPROVED = "0"
npm.cmd start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
$env:APPROVED = "1"
npm.cmd start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
Remove-Item Env:APPROVED
```

Для переходів із ранбуків у Windows PowerShell 5.1 замість рядка `git diff --cached --quiet || git commit ...` виконай git diff --cached, потім git commit лише якщо є зміни. Оператор || доступний у PowerShell 7 та Git Bash.

Зупинка програми на всіх ОС — Ctrl+C. Якщо переніс папку між ОС, виконай npm ci заново: node_modules між ОС не копіюємо.

## 8. Ліміти та типові проблеми

На безкоштовному рівні без поповнення OpenRouter документує **50 запитів на добу і 20 за хвилину**. Це спільна квота акаунта, не кожної моделі. Один оберт нашого циклу — один запит до моделі, тож один запуск може використати кілька запитів. Автоматичні тести квоту не витрачають. [Ліміти OpenRouter](https://openrouter.zendesk.com/hc/en-us/articles/39501163636379-OpenRouter-Rate-Limits-What-You-Need-to-Know).

На занятті спершу запускаємо тести поточного етапу, потім один живий приклад. Якщо провайдер перевантажений або денна квота вичерпана, продовжуємо на тестах і контрольних гілках. Перемикання моделі не відновлює спільну денну квоту. Поповнення балансу не є умовою продовження практики.

| Симптом | Що зробити |
|---|---|
| node/npm/git not found | Перезапусти термінал, звір встановлення та PATH. |
| Node старої версії | Встанови 26 Current; у nvm виконай nvm use 26.9.0. |
| GitHub 404 / repository not found | Перевір запрошення й обліковий запис, під яким авторизований Git. |
| Git просить user.name / user.email | Налаштуй їх локально командами з розділу 3. |
| npm.ps1 cannot be loaded | У PowerShell викликай npm.cmd або відкрий Git Bash. |
| Немає .env | Виконай npm run prepare; звір назву файла. |
| 401 | Звір ключ, чи він не відкликаний, чи немає зайвих пробілів. |
| 402 | Звір ID :free, стан ключа й текст помилки. Не переходь автоматично на платну модель. |
| 404 / no endpoints | Перевір поточний каталог і підтримку tools; вибери іншу :free-модель. |
| 429 | Перевір, чи це хвилинний/денний ліміт або навантаження провайдера. Дотримуйся Retry-After, якщо він є; поки працюй із тестами. |
| Помилка політики даних | Прочитай повідомлення й вимоги обраного провайдера в OpenRouter; обери сумісний із твоїми налаштуваннями безкоштовний endpoint. |
| length / немає tool call | Генерація могла обрізатися або провайдер не повернув потрібну дію. Вибери іншу :free-модель й повтори один раз. |

Безкоштовний API не дає гарантії безперебійності. Тести забезпечують продовження навчання, але їхній успіх не доводить, що живий провайдер доступний. Для прикладів використовуємо навчальні дані.

## 10. Context7: перевірка для організатора

Context7 MCP дає асистенту документацію бібліотек. Перед оновленням матеріалів перевіряємо через нього API, а точні поточні релізи — через npm. Учаснику для виконання самого harness достатньо підготовки вище.

Для Codex перевір наявність сервера:

```bash
codex mcp list
```

Якщо context7 відсутній:

```bash
codex mcp add context7 --url https://mcp.context7.com/mcp
```

Якщо клієнт відкриває авторизацію, заверши вхід у Context7 у браузері. Почни нову сесію Codex і перевір сервер через /mcp. Для інших асистентів є [офіційні інструкції Context7](https://context7.com/docs/resources/all-clients). Налаштування Codex описано в [офіційній документації MCP](https://developers.openai.com/codex/mcp).

Запит асистенту:

```text
Use Context7 MCP. Перевір API та сумісність ai, @openrouter/ai-sdk-provider,
zod, typescript, tsx і @types/node з нашого package.json.
Точні latest звір через npm view. Покажи джерела та відсутні версії.
Не оновлюй lockfile автоматично; спочатку перевір зміни на всіх етапах.
```

Context7 не завжди індексує потрібну patch-версію. Не називаємо документацію старого релізу підтвердженням нового; звіряємо npm metadata, типи встановленого пакета й наші тести. [Результати перевірки](dependencies.md).

## 11. Як переходити між етапами

step-05-call містить готовий результат теми 05. Якщо відстав, збережи свою спробу й відкрий цю контрольну точку перед темою 06. У кінці кожного ранбуку є точні команди.

Ранбуки та тести однакові в усіх гілках: тримай їх відкритими в редакторі. .env і node_modules залишаються на місці. Власні коміти зберігаються у твоїй робочій гілці. Після успішної підготовки відкрий [етап 01](01-model.md).

Практика: агент досліджує дискусії про harness engineering і coding agents. HN Search API працює без ключів; ключ потрібен лише OpenRouter. Готовий результат — .data/digest.md із посиланнями на теми й коментарі.
