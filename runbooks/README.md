## Логіка другої половини практики

08а — цикл; 08б — помилки API й retry. Це один блок про виконання та реакцію на збій, без окремої вправи з квотами. Далі 10 — контекст і фактичне завантаження AGENTS.md та rules; 11 — skills на вимогу; 12 — settings і guard перед дією.

Rules — текст для моделі. Skills — інструкції, повний текст яких додаємо після запиту. Settings — дані для коду. Guard — перевірка, яка виконує ці налаштування до виклику функції.

## Що саме перевіряємо після циклу

| Тема | Маленька зміна | Видимий результат |
|---|---|---|
| 08б | `maxRetries: 0` → `2` | Тест показує збій, повтор і один виконаний тул. |
| 10 | Читаємо `AGENTS.md`, потім додаємо rules | Спочатку друкуємо текст без API, потім бачимо його в `user` через TRACE. |
| 11 | Даємо моделі каталог skills і тул `readSkill` | Повний текст skill потрапляє в історію після виклику. |
| 12 | Читаємо settings і перевіряємо дозвіл | Без дозволу файл не змінюється, з дозволом запис відбувається. |

Вкладені інструкції, завантаження під час Read і перевірку перед Edit пояснюємо в темі 10. Власну підтримку цих механізмів не пишемо.

Після практики на слайдах обговорюємо памʼять між запусками: історію можна зберегти у файл чи базу, а потрібні записи шукати перед запитом. Пошук, зокрема гібридний і засоби Oracle, залишаються оглядом. Збереження сесій у цій практиці не реалізоване. Так само на прикладах розбираємо, як корисніший результат тула й перевірка відповіді допомагають агенту виконати завдання краще.

## Тести й налагодження

[Усі сценарії агента](../test/harness.test.mjs) · [середовище та ранбуки](../test/runbooks.test.mjs) · [підміна HTTP](../test/groq.mock.mjs) · [дані та повтори після 429](../test/rate-limit.test.mjs).

Тести мають номер теми в назві. Команда в ранбуку перевіряє цей і попередні етапи. На main та step-12-guard запускай npm test: 33 іменовані тести (34 разом із файлом HTTP-підміни). Перевіряємо структуру запитів, схеми аргументів, виконання, відповідність id, історію, ліміт, помилки, контекст, skills та дозвіл. HTTP у тестах підмінено; запит до API перевіряється окремо командою npm start із явно переданим завданням.


Починаючи з етапу 03: TRACE=1 npm start -- "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями." друкує тіло HTTP-запиту. Дивись reply.toolCalls, call.toolCallId та messages. Щоб зупинити програму в потрібному місці й перевірити змінні:

```bash
node --inspect-brk --import tsx --env-file-if-exists=.env src/main.ts "Знайди до трьох обговорень про harness engineering і coding agents за останні 7 днів. Прочитай коментарі та збережи український дайджест із посиланнями."
```

У редакторі підʼєднай налагоджувач Node.js і зупинись після generateText або всередині `executeTool` перед `agent.runTool`. Ctrl+C завершує процес.
